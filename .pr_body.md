## Description

Adds a rule-based order judge scorer: deterministic, explainable, **no model call, no randomness**. Scoring lives in `internal/judge` (pure function + tests) and is wired to its own opt-in HTTP listener in `cmd/tickerlight/main.go` — a separate `http.Server` from the console's public mux, so `/score` is never reachable through any existing route or ingress.

### Rule table (`internal/judge.Score`, first match wins)

| Rule | Condition | Score | Reason |
|---|---|---|---|
| non-positive qty | `qty <= 0` | `0.0` | `qty must be positive` |
| non-positive notional | `notional_cents <= 0` | `0.0` | `notional must be positive` |
| unknown side | `side` not `buy`/`sell` (case-insensitive) | `0.0` | `unknown side` |
| symbol not allowlisted | allowlist configured and symbol not in it | `0.0` | `symbol not in allowlist` |
| notional over ceiling | `notional_cents > ceiling_cents` (ceiling > 0) | `max(0.05, 1 - 0.5 * (notional_cents/ceiling_cents - 1))` | `notional exceeds per-order ceiling` |
| within limits | otherwise | `1.0` | `within configured limits` |

Weight rationale: a 100% overshoot of the ceiling (2x the allowed notional) halves the score; a `0.05` floor keeps a steep overshoot distinguishable from a hard reject (`0.0`) instead of collapsing into it. All four reject rules are checked before the ceiling penalty, so a disallowed symbol with a huge notional still reports the allowlist reason, not the penalty.

### Config keys (flag / env, console's existing mechanism — `flag` + `TICKERLIGHT_*` env fallback, explicit flag wins)

| Flag | Env | Default | Purpose |
|---|---|---|---|
| `-judge-enabled` | `TICKERLIGHT_JUDGE_ENABLED` | `false` | Turns the scorer listener on. Off by default. |
| `-judge-addr` | `TICKERLIGHT_JUDGE_ADDR` | `127.0.0.1:8091` | Scorer bind address. Must be loopback unless explicitly allowed. |
| `-judge-allow-non-loopback` | `TICKERLIGHT_JUDGE_ALLOW_NON_LOOPBACK` | `false` | Required to bind any non-loopback address; refused otherwise (`judge.ValidateBindAddr`). |
| `-judge-notional-ceiling-cents` | `TICKERLIGHT_JUDGE_NOTIONAL_CEILING_CENTS` | `5000` (= $50.00) | Per-order notional ceiling, in cents (minor units), matching the engine's per-order risk cap. `<=0` disables the ceiling check. |
| `-judge-allowlist` | `TICKERLIGHT_JUDGE_ALLOWLIST` | `""` (empty = any symbol) | Comma-separated symbol allowlist, case-insensitive match. |

### Pointing an engine at it

1. Run the console with the scorer on: `tickerlight -judge-enabled -judge-addr=127.0.0.1:8091 -judge-notional-ceiling-cents=5000 -judge-allowlist=AAPL,MSFT` (or the `TICKERLIGHT_JUDGE_*` env equivalents).
2. The engine `POST`s an order to `http://127.0.0.1:8091/score` with body `{"symbol":"AAPL","side":"buy","qty":2,"notional_cents":50000}` (cents, not dollars) and reads back `{"score":1,"reason":"within configured limits"}`.
3. Keep the engine and console co-located (same host/pod) — the listener defaults to loopback-only and a non-loopback bind is refused unless `-judge-allow-non-loopback`/`TICKERLIGHT_JUDGE_ALLOW_NON_LOOPBACK` is explicitly set.

## Caveats

- The scorer listener is a separate `http.Server` process-internal to the same binary; it is **not** behind the console's TLS/auth if any were added later — treat it as a trusted-network-only sidecar contract, matching "do not expose through any existing public route or ingress."
- Rule weights (penalty factor `0.5`, floor `0.05`) are compiled-in constants, not configurable — only the ceiling and allowlist thresholds are, per the task's requirement to make *thresholds* configurable. Happy to make the weights configurable too if that's wanted.
